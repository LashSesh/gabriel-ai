# PSE/Gabriel fit and exact owner extraction

Review scope: Gabriel `engine.py`, `canonical.py`, stream transition and incremental boundary; PSE top-level architecture/performance documents and production paths in graph, evidence, memory, topology and scale. This is a source-based component review, not an assertion that every test or every source line in the archive has been read by this reviewer. Separate review/build agents cover the remainder and execute PSE tests. Original uploaded and extracted sources remain unchanged.

## Decision

PSE is a synchronous stateful analysis pipeline for small constructed graphs. Its Rust ingestion rates are not comparable with Gabriel's durable verified owner. PSE has no per-tick SQLite transaction, crash recovery, complete semantic journal replay or exact command retry mechanism. Substituting PSE ingestion for Gabriel `Store.submit` would change the service being timed and remove guarantees.

The most directly useful transfer is PSE's demonstrated optimization principle: remove materialization that does not contribute additional semantics, while preserving a differential reference. This is applied concretely in the new `gabriel_runtime/fast_owner.py`, not by renaming or wrapping the PSE engine. No PSE Rust code or speculative topology classifier is linked into the owner. The original owner, canonical codec and numerical adapters remain byte-for-byte unchanged.

### Actual removable work

- `canonical.loads` invokes `canonical` again for validation (`canonical.py`, function `loads`).
- Consequently `_clone = loads(canonical(value))` validates twice, emits canonical JSON twice and parses once.
- `Store._transition` clones full pre-state and returned state/result; `submit` subsequently hashes and serializes state again. State already read and canonically checked from SQLite is hashed by serializing once more.
- `StreamRiskAdapter.apply` independently performs further full-state and result copies. Those remain unchanged, so the owner optimization has a clear residual cost and cannot promise unlimited speed.

### Implemented alternative

`FastStore` subclasses the reference owner, retaining its create/open, full replay audit, schema, limits, fingerprints, transaction and synchronization policy. It replaces only its own JSON round-trip isolation with checked structural copies, uses the validated stored state text for the pre-state digest, and uses one generated canonical post-state text for both hashing and SQLite persistence. No across-call cache is introduced. A proof detail easily missed in an attempted optimization is Python dictionary iteration: the reference round trip sorts all object keys. `checked_clone` therefore also sorts keys recursively, even if canonical equality alone would not notice a difference in an order-sensitive adapter.

The module compiled with `python -m py_compile`; independent differential, fault and benchmark agents own the subsequent executed results. This report must not be treated as those results before they arrive.

## Why PSE's remaining graph layer is not accepted as an execution certificate

1. **Evidence scope** (`pse-evidence/src/lib.rs`, `verify_content_address`, approximately lines 110–135): the crystal identity hashes only region, stability score, creation index, free energy and carrier instance. It excludes the constraint program, evidence chain, gate/consensus proof, topology signature, versions and provenance. `verify_crystal` checks a supplied `kairos` boolean, not recomputation of eight gate inequalities; unknown operators are not rejected if absent from the pin map. Evidence hashes cover entry content rather than content plus previous link, and the first entry's predecessor is not checked. Timestamps and scores are floating point comparisons without a finite-value guard in this verifier. These are concrete limits; this API is not a complete semantic replay or authenticity proof.
2. **Approximate memory** (`pse-memory/src/lib.rs`, `lookup`, `similarity`, `compute_content_hash`): weighted cosine/resonance/confidence similarity is a heuristic. Matching a small topology descriptor or unlabeled graph class does not imply equality of the numerical state, payload, future evolution or an exact transition. Its `content_hash` binds a restricted crystal fingerprint, not all semantic fields. The vector described as LRU is FIFO because lookups do not refresh order. `canonical_index` is not evicted when bounded signatures are evicted; its ID vectors can grow independently. Reported estimated time saved adds an assumed 1 ms, not measured execution savings.
3. **Graph construction and capacity** (`pse-graph/src/lib.rs`, `apply_observations`, lines 349 onwards): capacity checks `current IDs + batch length`, which overcounts repeated sources and omits extra vertices from binary edge payloads. It is not an exact vertex or memory bound. Histories, tensor snapshots and hot payload copies are retained without automatic retention enforcement. Co-occurring source IDs form a complete orientation for up to 64 unique sources and a sparse ring-like construction beyond that boundary. This is a chosen graph model, not discovered physical causality.
4. **Descriptor semantics** (`pse-graph/src/lib.rs`, `compute_spectral_gap`, lines 711 onwards): the simple graph signature uses degree spread and a fixed fallback 0.1 beyond 100 vertices under a spectral-gap name. Five embedding coordinates are chosen normalized graph descriptors, not a proof that five degrees of freedom suffice for all dynamic systems. Directed degree balance is not a causal identification result.
5. **Spectral algorithm limitation** (`pse-topology/src/lib.rs`, `spectral_decompose_partial`, around lines 301–447): partial Lanczos starts from an alternating-sign vector. For even `n` it is orthogonal to the constant nullspace of a connected Laplacian. It cannot generally establish that the first two retained Ritz values are the true two smallest eigenvalues, yet `build_spectral_result` names the second one `spectral_gap`. For a 32-vertex complete graph with one directed unit-weight edge per unordered pair, the symmetrized Laplacian has true gap 16; the alternating vector is itself a 16-eigenvector, so breakdown yields a single Ritz value and the code's gap fallback is zero. This is an analytic counterexample pending separate executed Rust reproduction. The expression `sqrt(2*gap)` on an unnormalized weighted Laplacian is not a universally dimensionless Cheeger certificate.
6. **Fixed-point meaning** (`pse-topology/src/lib.rs`, `FixpointDetector`): convergence tests successive active vertex sets using Jaccard distance. A stable active set with changing edge weights, phases, embeddings or archives can satisfy it. It does not establish a fixed point or contraction of the full engine state.
7. **Scale boundaries** (`pse-scale/src/lib.rs`, `multi_scale_tick`, around lines 939 and 1040): elapsed-time branch decisions still exist despite the deterministic topology-budget change. The stopwatch is started immediately before the check, so this is neither a useful work deadline nor a strict deterministic decision under arbitrary scheduling. The bisection stop condition creates a new cluster even when `next_id >= max_clusters`, allowing pending recursive branches to exceed that advertised cap. `apply_bridge_coupling` exists separately, but the shown multiscale tick's bridge steps evaluate active flags rather than call the coupling function; delayed dynamics should not be inferred from the metadata alone.

## Follow-up boundary

PSE can remain a separately labelled, bounded exploratory graph-analysis source. Admitting it into a verified decision profile would require an explicit input graph model, bounded retention and resource semantics, complete typed state serialization, transactional error behavior, corrected numerical eigenvalue checks and evidence coverage, and validation of the scientific value of graph-derived features. The present phase intentionally completes a smaller exact improvement to the actual Gabriel runtime rather than claiming these absent properties.
